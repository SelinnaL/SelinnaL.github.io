MIT Motorsports: Autonomous Racecar

Driverless perception, planning, and control integrated on our team's RC testbed.

ROS2 Python C++
Overview

The driverless system must autonomously navigate the Formula SAE Driverless events: Acceleration, Skidpad, Autocross (and Trackdrive in the future) and pass static and dynamic safety tech inspections. Track boundaries are marked by blue cones on the left, yellow cones on the right, and orange cones for timing/boundary lines. The car relies entirely on its on-car autonomy stack to stay within bounds. We've made our physical development testbed fully driverless so we have a real testing pipeline.

Hardware & sensors
  • Cameras: 3x PoE — 2x Blackfly S BFS-PGE-31S4C + 1x BFS-PGE-1637C
  • LiDAR: Ouster OS1, 128 channels
  • IMU: VectorNav VN-300
  • GPS: u-blox ZED-F9P-02B RTK (SparkFun GPS-RTK-SMA kit)
  • Drive / steer: ODrive S1 + magnetic encoder for the traction motor; servo via Jetson GPIO for steering
  • Networking: 5-port 10G Ethernet hub, PTP-synced between cameras, LiDAR, and compute
  • Compute: NVIDIA Jetson Orin AGX 64 GB
Software stack
  • Perception: Ground removal → spatial / density filtering → LiDAR cluster extraction for cone positions → project clusters into the camera frame to segment color.
  • State estimation: ROS 2 robot_localization EKF at 100 Hz in 2D. Indoor mode fuses VN-300 IMU + ground speed odometry; outdoor mode adds RTK GPS via navsat_transform_node.
  • Planning: Delaunay triangulation over perceived cone centroids → midpoint graph → Dijkstra shortest path → univariate spline smoothing before handoff to the controller.
  • Control: Pure pursuit lateral controller using a geometric bicycle model. Velocity commands go over USB to an ODrive motor controller, which handles low-level closed-loop motor control and publishes odometry back to state estimation.
