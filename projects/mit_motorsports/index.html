MIT Motorsports: Autonomous RC Car

Autonomous driving on the team testbed: perception, planning, and control integrated on an RC Car.

ROS2 Python C++

Overview

The overarching goal of the driverless system is to autonomously navigate dynamic events defined by the Formula SAE Driverless competition as well as pass both static and dynamic safety tech inspections. The vehicle must successfully compete in events such as Acceleration, Skidpad, and Autocross (and Trackdrive in the future). To accomplish this, the vehicle relies entirely on its on car autonomy stack to stay within the track boundaries, which are marked by blue cones to the left, yellow cones to the right, and orange cones denoting timing and boundary lines. Our major progress for this year was establishing a fully functional testing pipeline by making our physical development testbed driverless.

Technical Architecture

Software

  • Perception: The perception pipeline starts with ground removal and filters out unlikely points and clusters based on spatial position and density. The remaining LiDAR points are clustered to identify physical cone positions. We then project these cone clusters into the camera frame to extract and segment their color information.
  • State Estimation: ROS 2 robot_localization package to run an Extended Kalman Filter (EKF) at 100Hz in 2D mode. We currently are using dynamic configurations for indoor vs. outdoor testing, as using GPS requires us to have an open roof. The indoor mode fuses VN-300 IMU data and ground speed odometry. The outdoor mode fuses RTK GPS data via a navsat_transform_node for robust global positioning in addition to IMU and speed.
  • Planning: Delaunay triangulation-based path planner that subscribes to the perceived cone centroids. It triangulates the visible track boundaries to build a spatial graph, calculates the midpoints between valid cone pairs, and uses Dijkstra's algorithm to find the shortest viable path. To ensure smooth steering, the resulting path is refined using a univariate spline before being published to the controller.
  • Control: Pure pursuit lateral controller that subscribes to the path generated by the planner. On each control loop, it selects the furthest midpoint by Euclidean distance and applies a geometric bicycle steering law to constantly chase the lookahead point, publishing the calculated steering angle and target velocity commands. The calculated target velocity commands are sent via USB to an ODrive motor controller, which serves as the vehicle's drive-by-wire system. The ODrive handles the low-level closed-loop control of the brushless traction motor while simultaneously publishing high-frequency ground speed odometry back to the state estimation pipeline.

Hardware

  • Sensors:
    • 3 Power over Ethernet (PoE) cameras: 2x Blackfly S BFS-PGE-31S4C, 1x Blackfly S BFS-PGE-1637C
    • Ouster OS1 128-channel LiDAR
    • ODrive S1 + Magnetic Encoder from ODrive (Correvit ground speed sensor on full scale car)
    • VectorNav VN-300 IMU
    • ZED-F9P-02B GNSS RTK GPS (from the SparkFun GPS-RTK-SMA Kit)
  • Steering & Drive: ODrive for controlling the motor, and a servo connected via GPIO to the Jetson Oring for steering.
  • Networking: All systems route through a 5-port Ethernet hub capable of 10G per port. The hub connects directly to the NVIDIA Orin, with the cameras and LiDAR strictly PTP synced over the network.
  • Compute: NVIDIA Jetson Orin AGX 64GB
